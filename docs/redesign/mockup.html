01 — Flagship

GGBA — a Game Boy Advance emulator, written from scratch in Rust

No third-party emulator code, no BIOS image, no ROMs. An ARM7TDMI interpreter validated against gba-tests, a full PPU, an APU, and a Jetpack Compose Android shell on top. The emu-core crate deliberately knows nothing about the GBA, so a second console costs no UI work.

One page per shipped app, each generated from a Markdown file so adding an app is a single file. Google Play requires a reachable privacy policy URL for every listing, so GGBA needs one before it can ship.

Better Beta is deliberately absent. It's a separate company with its own domain and its own policy at betterbeta.io/privacy — a second copy on a personal site would be a liability, not a convenience, since the two would drift apart and only one of them is the operative document.

I will not write these from guesswork

A policy that misdescribes what an app collects is a legal problem, not a copy problem. For each app: does it collect anything, does it use analytics or crash reporting, does it have accounts, does it phone home? For GGBA I expect the honest answer is close to "nothing leaves the device" — which makes for a short, strong policy. You confirm it, I won't assume.

Three apps, not four — Better Beta's policy lives on its own domain and stays there.

  posthog.init('phc_YOUR_PROJECT_KEY', {
    api_host:        'https://eu.i.posthog.com',
    defaults:        '2025-05-24',
    person_profiles: 'identified_only',  // no profile for drive-by visits
    persistence:     'memory'             // cookieless — no consent banner
  });
</script>

Named events on top of autocapture: project_card_click, case_study_scroll_depth, blog_post_read, outbound_click. Those are what answer "which project is actually pulling attention".

One limitation stated up front: the usual ad-blocker workaround is a reverse proxy on your own domain, and GitHub Pages has no proxy layer. Expect 10–30% of traffic to be invisible. Fine for trends, not for absolute counts.
